# Contributing to MonoNeural

Thank you for your interest in contributing to MonoNeural.

MonoNeural is an open-source educational platform designed to make artificial intelligence concepts easier to understand through interactive learning and experimentation. Contributions of all sizes are welcome, including bug fixes, documentation improvements, UI enhancements, performance optimizations, and new features.

Please review these guidelines before creating issues or submitting pull requests.

<br>

## Code of Conduct

This project follows a Code of Conduct to ensure a welcoming and respectful environment for everyone.

Please read the [CODE_OF_CONDUCT](CODE_OF_CONDUCT.md) before participating in discussions or contributions.

<br>

## Ways to Contribute

There are several ways to contribute to MonoNeural:

### Documentation Improvements

Examples:

- fixing grammar mistakes
- improving explanations
- correcting outdated content
- adding missing information

### Bug Fixes

Examples:

- resolving unexpected behavior
- fixing UI inconsistencies
- correcting calculation issues
- fixing responsive layout problems

### Feature Improvements

Examples:

- improving existing functionality
- enhancing user experience
- improving visual feedback
- extending neuron functionality

### Repository Improvements

Examples:

- improving workflows
- refining templates
- improving development tooling
- improving project structure

<br>

## Before Creating an Issue

Please review existing issues before creating a new one.

Before opening a new issue:

- search for similar issues
- verify that the problem still exists
- include clear reproduction steps
- provide screenshots if applicable
- include browser and environment information

Issue templates are available and should be used whenever possible.

<br>

## Development Setup

Clone the repository:

```bash
git clone https://github.com/dulanjayabhanu/mononeural.git
```

Move into the project directory:

```bash
cd mononeural
```

Install dependencies:

```bash
npm install
```

Start the development server:

```bash
npm run dev
```

Build for production:

```bash
npm run build
```

Preview production build:

```bash
npm run preview
```

<br>

## Branch Guidelines

Please avoid making changes directly on the main branch.

Create a dedicated branch for your work:

```bash
git checkout -b feature/your-feature-name
```

Examples:

```bash
feature/neuron-chart-improvement
fix/training-calculation-error
docs/update-trainer-guide
```

<br>

## Commit Guidelines

MonoNeural follows Conventional Commits.

Examples:

```bash
feat: add neuron parameter export functionality

fix: resolve prediction calculation issue

docs: improve trainer documentation

refactor: simplify neuron state handling

chore: update repository configuration
```

Please write clear and meaningful commit messages.

<br>

## Pull Request Guidelines

Before submitting a pull request:

- review your changes
- ensure the application builds successfully
- verify there are no console errors or warnings
- test on desktop and mobile devices if applicable
- test both light and dark themes
- update documentation if required
- link related issues if applicable

Please keep pull requests focused on a single change whenever possible.

<br>

## Review Process

All pull requests are reviewed before merging.

During review:

- maintainers may request modifications
- additional clarification may be requested
- suggestions for improvement may be provided

The goal of review is to maintain code quality, consistency, and long-term maintainability.

<br>

## Questions

If you are unsure about a contribution idea, open an issue before starting implementation.

Discussion before development can help avoid duplicated work and reduce unnecessary effort.

<br>

Thank you for helping improve MonoNeural and supporting open-source learning.
